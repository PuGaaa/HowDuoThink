# Web 端改版（账号 / AI 会话 / 布局与液态玻璃）实施计划

> **给执行者：** 必须使用 subagent-driven-development（推荐）或 executing-plans 逐任务实现本计划。步骤用复选框 `- [ ]` 追踪。

**目标：** 短信用户可设置密码、登录后有默认/可上传头像、AI 排错有持久化会话与多轮上文且报错不再外泄、全站 `#FAFAFA` 宽幅布局带液态玻璃质感。

**架构：** 后端沿用 features 分层（router→service→repo，SQL 只在 repo/数据层）；会话两表走 Alembic 0013；头像上传复用 assets 域的 OSS 通道但落独立 `user-avatar` 分类并在公开清单中排除。前端按域拆组件（account / ai / layout）+ 共享 composables；玻璃材质集中在一个 CSS 文件。

**技术栈：** FastAPI + SQLite 方言（core/db 翻译 MySQL）、Alembic、Pydantic v2；Nuxt 3 `<script setup>` + TypeScript；pytest（`cd server && set -a && . ./.env.dev.local && set +a && COOKIE_SECURE= .venv/bin/python -m pytest tests/ -q -W ignore`；本机基线另有 4 个环境依赖失败：test_assets 的 OSS 未配置用例与 manifest 用例、test_sms_gate 两条，见台账）。

**规格：** `docs/superpowers/specs/2026-11-12-web-改版-design.md`（执行者两份都要读）

## 全局约束

- 新 SQL 用 SQLite 方言（`?` 占位 / `datetime('now')` / `ON CONFLICT … DO UPDATE`），由 core/db 翻译；方言规则只动 core/db.py。
- 测试密码一律从 `os.environ["ADMIN_PASSWORD"]` 派生，不落明文；跑测前 `cd server`。
- 后端接口出参 camelCase（alias 模式，如 `conversationId`）；错误不泄露堆栈/环境变量名。
- 前端文件按域放：`components/{account,ai,layout,common}/`、`composables/`；组件显式 import（同 me.vue 引 SubmissionCard 的现有写法）。
- 布局取值逐字：`--bg: #FAFAFA`、内容区 max-width 1280px、顶栏通栏吸顶、600px 以下单栏。
- 头像上传：仅 png/jpg/jpeg/webp、≤2MB、每人每日 10 次、OSS 前缀 `<OSS_KEY_PREFIX>/user-avatar/…`、不进公共头像池与公开清单。
- AI 会话：每人上限 100 个（超出删最久未更新）、标题取首问前 30 字、上文取最近 3 轮 6 条、检索词 = 上一问 + 当前问、失败不落库。
- 报错文案逐字：前端 401 → `请先登录后再提问`；其余 → `服务暂时不可用，请稍后再试`；后端不可用提示 → `AI 服务暂未开放，稍后再试`。
- 前端无单测框架：前端任务的验证 = `npm run typecheck`（在 web/ 下）+ dev server 截图（浏览器自动化，尺寸 1920×1080 / 393×852 / 375×667）。
- 全程在新分支 `feat/web-revamp` 上；用户既有未提交改动（app.vue 隐私链接、privacy.vue）原样保留，不纳入本分支提交。

## 评审聚焦点

1. 用别人的 `conversationId` 续聊 → 必须 404，不能读写（测试在任务 5）。
2. 列表 `limit>50` → 422；头像上传 svg/gif/超 2MB → 400，OSS 未配 → 503（测试在任务 1、2、5）。
3. 模型抛异常 → 返回友好文案且不含异常文本，且该次提问不产生任何会话/消息行（测试在任务 4）。
4. 头像池为空或请求失败 → 显示昵称首字占位，且不向 `PATCH /api/me` 写入空值（验证在任务 6 截图步骤）。
5. 不支持 `backdrop-filter` 的浏览器 → 弹层/顶栏退回高不透明实底，文字仍可读（验证在任务 11、13 截图步骤）。
