# 001 · 产品形态与关键决策

日期：2026-09-27 · 状态：已定

## 决策

| 议题 | 决策 | 理由 |
|---|---|---|
| 核心形态 | 诊断推理闯关（非课程/检查单库） | 同时训练假设能力与验证成本意识，可融合其他形态 |
| 首发用户 | 自己 + 身边 agent 程序员 | 痛点最直接，快速迭代出对的形态再推广 |
| 载体 | uni-app X 蒸汽模式，H5 先行 → iOS | 一套代码；H5 编译回落 VDOM 属官方正常行为 |
| 验证交互 | 预置动作清单（v0） | 内容可控可审核；自由输入+AI 应答留二期 |
| 假设板 | 预置池勾选 + 自由文字备注 | 可判定可计分，同时不扼杀真实思维 |
| 拟真度 | 关键行风格 | 信息密度高、生产快，首批铺量优先 |
| 动态案例 | 首批静态，schema 预留 effects | 最快验证核心玩法；重启陷阱二期做 |
| 首批题库 | 按层专题 × 高频故障，10 题 | 两条策略合并：每题主打一层契约，拼全栈地图 |
| 内容生产 | AI 生成 + 人工审核（双身份走验）+ 事故报告改编 | 内容是生死题，管线先行 |
| 趣味系统 | 内心小动物 ×5（伽菜子式外化内心） | 趣味系统与教学系统合并：每只动物对应一种认知偏误 |
| 动物语气 | 平时冷面吐槽，三角龙（挫败）只暖不刺 | 幽默与安全的最稳组合 |
| 美术 | emoji + CSS 动画先行 | 零美术成本验证趣味系统，设定集先立 |
| 评分 | S/A/B/C = 正确 × 预算效率 × 错误指认 | 把 token 成本意识变成游戏机制 |

## 明确不做（v0）

后端实现、社区 UGC、自由输入+AI 在线应答、动态案例、正式美术、审核台 UI、热更新、商业化。
