## Phase 1 · 内容量产（M2 完成）

> 目标：关卡从 11 → 30，每关过 validate + gate 双检

### 1.1 出题排期（按篇-章优先级）

| 批次 | 章 | 关卡 | 难度 | 优先 |
|---|---|---|---|---|
| **已交付** | 接入层 | SSL 链 / DNS / CORS | L1-L2 | ✓ |
| **已交付** | 构建 | 白屏 / 依赖冲突 | L1 | ✓ |
| **已交付** | 数据 | 连接池 / 缓存 | L2 | ✓ |
| **已交付** | 并发 | 秒杀超卖 | L3 | ✓ |
| **P5a** | 数据 | 慢查询（增 1 关凑 3）| L2 | 高 |
| **P5a** | 运行时 | OOM 泄漏（增 1 关凑 2）| L3 | 高 |
| **P5a** | 并发 | 幂等失效（增 1 关凑 2）| L3 | 高 |
| **P5b** | 接入层 | Nginx 配置陷阱 | L2 | 中 |
| **P5b** | 可观测 | 告警风暴 / 日志采样 | L3 | 中 |
| **P5c** | 安全 | 密钥泄漏 / 权限绕过 | L2-L3 | 低 |
| **P5c** | 容量 | 限流穿透 / 降级演练 | L3 | 低 |

### 1.2 AI 辅助转化工具

投稿 → 关卡草稿的 AI 起草管线：
- 后端加 `POST /api/admin/submissions/:sid/ai-draft`，调 GLM 按写作规范生成骨架
- 管理端编辑器加"AI 起草"按钮，生成后人工校准
- 依赖：server 加 httpx 调 GLM API 的封装（复用 figma-rpc 的 httpx 模式）

### 1.3 验收标准

- 每关 validate.mjs 全绿 + gate.py 门禁通过
- App 端试玩一遍无报错
- 章节地图对应节点从"即将上线"变可玩

## Phase 2 · 部署上线

> 目标：三端可公网访问

### 2.1 后端（server/）

- Dockerfile：python:3.12-slim + requirements + uvicorn
- systemd 服务（非 Docker 方案）
- SQLite 文件持久化路径环境变量化
- 环境变量清单：`GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` / `JWT_SECRET` / `ADMIN_PASSWORD`

### 2.2 Web 社区（web/）

- `nuxt build` → `.output/` → Node SSR 或静态
- `API_BASE` 环境变量指向后端域名
- 域名 HTTPS（Caddy / Nginx + certbot）

### 2.3 App（H5 / iOS）

- `config.ts` 的 `API_BASE` 切线上地址
- H5 构建产物部署（CDN / 静态托管）
- iOS 打包（后续，需开发者账号）
