# 案例写作规范

> 本文档是本产品的**核心交付物**。AI 生成案例的 prompt 从它派生，人工审核的 checklist 也从它派生。
> 规范改动必须同步 `content/prompts/` 里的模板。

## 0. 一句话宗旨

每道题是在搭一个**"诊断推理的舞台"**：玩家必须在证据不足的迷雾里，练习"假设空间 × 验证成本"的排序决策。题目质量 = 玩家的每一步选择是否真的在训练这个习惯。

## 1. 一道题的六个部件

### ① 症状面（scene）

**必填三个维度**，缺一不可：

| 维度 | 内容 | 设计要求 |
|---|---|---|
| 报错关键行 | 真实感的报错/日志关键行 | 不得直白点名根因（红线），但"形状"必须给懂行的人留推理抓手 |
| 时间线 | 何时开始、与什么变更相关 | 变更必须写进时间线（发版/配置/换供应商/升级依赖），训练"变更相关≠变更因果"的敏感度 |
| 影响面 | 多少用户、哪个端、哪个区域 | 影响面信息初始**不给**，做成 1⚡ 的"查影响范围"动作——专家链第一步永远是它 |

另需：`role`（玩家角色代入）、`architecture`（一句话链路图，如 `App → CDN → Nginx → 服务 → DB`）。

**形状设计的意义**：502 vs 504、"部分失败" vs "全挂"、哪个端/区域/版本——错误码和分布的*形状*本身就是证据。好题的形状信号能被高手读出来，但不认识形状的人也能靠动作走完。

### ② 假设空间（hypotheses）

- 5~8 个假设，**干扰项必须平权**：对不知道答案的人，每个假设都同样合理
- **铁律：每个干扰假设必须存在一条低成本排除路径**（指向某个动作）。没有排除路径的不是干扰项，是刁难
- 正确假设混在池中，不标记

### ③ 动作与证据（actions）

- 8~15 个预置动作，每个标注成本 ⚡（1~10）
- **信息论视角**：专家路径 = 用最少 ⚡ 买够定位信息。每个动作的 `gain`（信息增益）必须是 high / mid / low / none 之一，且与证据内容自洽
- **必须混入"贵且低信息"动作**（真实排错里大量存在），练成本纪律
- **L2 起必须包含重启/回滚类危险动作**（`danger: true`，成本 8~10⚡；L1 教学关豁免）：证据应显示"症状短暂消失/依旧，现场被破坏"，为二期动态重启陷阱埋点
- **证据全局自洽**（红线）：根因、每个动作返回的证据、影响面分布、时间戳必须互相咬合。一处不自洽，整个产品不可信
- **噪声必须存在**（红线）：日志里混 1~2 条与本案无关的告警（真实故障从不干净），且要在某处可被收线（红鲱鱼必须有明确收线动作，不能永远悬着）

### ④ 专家链（expertChain）

每步**四段式**，缺一即打回：

```
thought     观察到了什么（用第一人称，体现当时的思考）
update      假设如何更新（升权/降权/排除谁）
actionId    选了哪个动作（可为空，纯推理步）
why         为什么选这个动作——成本/信息增益的排序理由【教学核心，必写】
conclusion  排除了什么/确认了什么
```

- 必须包含新手永远不会做的动作："先看影响面"、"先分清故障在哪一跳"
- **必须包含一步停止规则**：说明"证据链何时闭合、为什么继续收集不会改变行动"。教"何时停止"和教"如何定位"一样重要
- 结论句写修复方案（一句话），不复盘（复盘交给 lessons）

### ⑤ 难度设计（表面旋钮 + 推理六维，出题前逐维自检）

#### 5.1 表面旋钮（四个独立可调——量"谜面大小"，量不出推理难度）

| 旋钮 | L1 教学关 | L2 标准 | L3 地狱 |
|---|---|---|---|
| 假设空间大小 | 3~4 个 | 5~6 个 | 7~8 个 |
| 噪声量 | 无噪声，带引导 | 1~2 条噪声 | 3 条以上 + 噪声会误导 |
| 预算松紧 | 专家成本 ×3 以内随便花 | ×2 以内 | ×1.5 以内 |
| 干扰项迷惑度 | 排除动作明显 | 需要两步排除 | 干扰项本身部分成立 |

> 注意：假设数 ≠ 难度。8 个平权假设若证据直陈（查了就是答案），仍是 L1。
> L3 可用进阶手段：双因叠加（一个表因一个根因）、症状中途演化（二期动态支持）。

#### 5.2 推理六维（题目本身的难度——量"从证据到根因有多远"）

| 维度 | L1 | L2 | L3 |
|---|---|---|---|
| ① 推理距离：遮住根因只读证据，普通人几步喊出答案 | 直陈：某条证据直接写着根因（异常消息指出哪个解引用为 null） | 单跳推断：证据给事实，推 1~2 步到根因（延迟曲线 × 立读时间线 → 撞窗口） | 链式/机制推断：多证据组合 + 机制解释才到根因（提前量随创建时刻漂移 → 时区混算） |
| ② 证据形态 | 直陈式：日志/报错直给 | 对比式：两份材料对照才出结论（对时表、双 diff、双环境对照） | 量化/指纹式：曲线形状、窗口函数、杀伤模型对账 |
| ③ 知识层次 | 常识层（判空、键名对齐、先看影响面） | 领域机制（FIFO 队头阻塞、复制延迟、信号语义） | 反直觉机制（PMTUD 黑洞、银行家舍入、惊群乘法、语义漂移） |
| ④ 反直觉度 | 答案与直觉一致 | 直觉给对方向、细节错 | 直觉给反方向（重跑就绿 = 哨兵哑火；恢复动作引发二次事故） |
| ⑤ 跨层跨度 | 单层单跳 | 同层深挖或跨 2 跳 | 跨端/跨系统/跨职能边界（三端归一、跨服务关联链） |
| ⑥ 陷阱主动性 | 无陷阱 | 有危险动作陷阱（回滚破坏现场） | 有"看似正确"的陷阱（追认错误语义、扩容治惊群、回退解耦） |

**逐维检验法**：把根因遮住，只把证据摊在桌上——
- 一眼喊出根因 = ①L1；需要对照两样东西 = ②L2 起；需要说出"机制上为什么会这样" = ③L3。

#### 5.3 定级与篇映射

- **定级**：六维各自判 L1/L2/L3，取**中位数**为题目难度；任意两维 L3 可标 L3（单维拉爆不算）。
- **篇映射**（难度按篇递增，写进关卡表前先自检）：
  - 每章至多 1 个 L3，且必须是章尾**结业关**（评审/决策/压轴排查）——L3 不是散装难度，是章的收尾考试
  - 学徒篇：L1 起步 + L2 为主 + 结业 L3 ×1；六维 L3 维度（反直觉/陷阱/跨层）仅结业关允许
  - 工兵篇：L2 为主 + 结业 L3 ×1，L1 仅作章首入门
  - 大师篇：L2/L3 并重，L3 为主力难度，结业关必为 L3
- **与标签解耦**：difficulty 标签必须由六维自检产生，不许"因为它在大师篇所以标 L3"。

#### 5.4 存量校准注记（2026-10-07 审计）

按六维复盘存量：学徒篇当时混入 5 个 L3（假设空间 8.9 ≈ 大师篇 8.5）、工兵篇仅 1 个 L1。
后续批次出题按本节执行；存量错档题在各自章精修时降档/重修。
### ⑥ 动态性（v0 静态）

v0 所有动作查表返回证据。schema 预留 `effects` 字段，二期动态题（重启清空队列、等待使缓存过期、症状演化）才启用。写作时**不要**为静态题编造依赖时序的证据。

## 2. 拟真度：关键行风格（首批统一）

日志/报错只写**关键行 + 省略号**，一屏读完：

```
✅ 好的写法
2026-09-27 22:47:03 [error] TLS handshake error (certificate verify failed)
2026-09-27 22:47:03 [warn] upstream timeout (偶发，与本案无关的噪声)
...（重复刷屏 400+ 行）

❌ 坏的写法
完整堆栈 30 行 / 时间戳精确到毫秒的连续日志块 / 需要滚动三屏才能读完
```

报错文案要用**真实世界会出现的原文**（如 `Verify return code: 21`），不自己发明报错格式。

## 3. 评分与成本基准

- `expertCost` = 标准专家路径的动作成本之和（含 1⚡ 影响面 + 实锤动作 + 解释分布的确认动作）
- 评级：S = 答对且成本 ≤ expertCost×1.2 且零次错误指认；A = ≤×1.8 且错 ≤1 次；B = 答对；F = 两次错误指认出局
- **双路径原则**：最优解至少存在两条不同顺序的合理路径（红线）。否则玩家在"猜作者心思"，不在练推理

## 4. 复盘沉淀（lessons）

- 每题 2~4 条诊断检查单，格式：`text`（这条经验的一句话）+ `principle`（这层的契约/原理注解）
- principle 必须回答"**为什么这一层是这样设计的**"——所有题的 principle 拼起来，就是碎片化的全栈思维地图

## 5. 审核红线（一票否决，pipeline + 人工共用）

- [ ] 证据不自洽（任何证据与根因/分布/时间线矛盾）
- [ ] 最优路径唯一
- [ ] 存在没有排除路径的干扰假设
- [ ] 报错直白点名根因
- [ ] 零噪声 / 红鲱鱼悬而未收
- [ ] 专家链只说结论不讲 why / 缺停止规则步
- [ ] 危险动作缺失（L2 以上必须含重启或回滚类）
- [ ] 影响面动作缺失或成本 ≠1⚡ / 专家链第一步不是它
- [ ] 技术事实错误（端口号、默认值、报错原文等——人工重点核对）
- [ ] lessons 的 principle 没讲层契约

## 6. 与 schema 的字段对照

| 部件 | schema 字段（app/types/case.ts） |
|---|---|
| 症状面 | `scene.role / architecture / symptoms / timeline / impactHint` |
| 假设空间 | `hypotheses[]`（含 `excludeActionId`） |
| 动作与证据 | `actions[]`（`cost / result / gain / danger`，预留 `effects`） |
| 专家链 | `expertChain[]`（四段式 + `actionId` 可空） |
| 评分基准 | `expertCost`、`restartActionId` |
| 复盘沉淀 | `lessons[]`（`text / principle`） |
| 元信息 | `id / title / domain / layer / difficulty / intro` |
