# 备份与恢复

> **警示（操作前必读）**
>
> 1. 基线迁移的 `downgrade()` 会 **DROP 全部业务表**——执行任何 downgrade 之前，必须先完成一次手动备份（见下文「2. 手动备份」）。
> 2. 恢复演练请使用独立的 compose 项目名（`docker compose -p <name> ...`）另起一套栈操作，**勿在生产栈上直接演练恢复**。

## 1. 备份机制

`backup` 侧车服务随 `server/docker-compose.yml` 部署：每日一次（自容器启动时刻起算，间隔 86400 秒）对全库做 `mysqldump --single-transaction` 并 gzip 写入 `backups` 卷，文件名 `hdx-YYYY-MM-DD.sql.gz`；保留最近 7 天，过期产物自动清理。

- 查看 `backups` 卷在宿主机上的实际位置（`<project>` 为 compose 项目名，默认为 `server`）：

  ```bash
  docker volume inspect <project>_backups
  ```

- 查看备份产物列表（以下命令默认在 `server/` 目录执行，或加 `-f server/docker-compose.yml`）：

  ```bash
  docker compose exec backup ls -lh /backups
  ```

## 2. 手动备份

```bash
docker compose exec mysql sh -c 'exec mysqldump --single-transaction --no-tablespaces -uroot -p"$MYSQL_ROOT_PASSWORD" ${MYSQL_DATABASE}' | gzip > manual-$(date +%F).sql.gz
```

- root 密码来自 mysql 容器自身的 env（`MYSQL_ROOT_PASSWORD`，由 compose 从 `.env` 插值注入），整段在容器内 `sh -c` 展开，不进命令行参数、不进终端回显，**勿手动回显**。
- 产物 `manual-YYYY-MM-DD.sql.gz` 落在当前目录。

## 3. 恢复

```bash
gunzip -c <备份文件> | docker compose exec -T mysql mysql -uroot -p"$MYSQL_ROOT_PASSWORD" ${MYSQL_DATABASE}
```

- 此命令中 `$MYSQL_ROOT_PASSWORD` 与 `${MYSQL_DATABASE}` 在**当前宿主机 shell** 展开，需先在 shell 中备好这两个变量（如 source 对应的 env 文件）；同样不要回显密码。
- 演练场景请按文首警示使用独立项目名（`-p <name>`）。

恢复完成后核查要点：

- 核心业务表行数与备份前一致（users / cases / settings 等）；
- `alembic_version` 表存在，且其 `version_num` 等于当前代码库的迁移 head。
