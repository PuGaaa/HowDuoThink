## 缺口（按严重度）

### 1. 设计层思维没有关卡形式（最独特的机会）
理念说"根因常在设计时种下"，但 16 关全是**事后排查**皮肤（出事了 → 查 → 修）。架构设计思维、程序设计思维只能顺带提到（如 msg-order 的版本号校验）。
**补法：设计评审关**——不发故障，给一段含设计取舍的方案（缓存窗口/重试/超时），玩家在评审会上找出会出事的取舍。验证"皮肤会演进"。

### 2. 安全思维缺位
理念列了安全思维，但 16 关无真正安全案例：ssl-chain 讲可用性，nginx-trap 是配置。缺：接口无鉴权、日志泄露 token、越权访问。
**补法：安全域案例 1~2 关。**

### 3. 产品思维训练偏弱
影响面动作存在，但视角是"定位手段"；没有一关逼玩家回答"这对业务/用户意味着什么、该不该现在回滚"的权衡。回滚 8⚡ 的成本博弈算部分覆盖。

### 4. 运行时章断档
全栈视野六大层中，运行时仅 oom-leak 一关（线程/内存/GC/句柄泄漏空白）。

### 5. 情绪只外化、未驯服
五兽把情绪搬出来了（理念第 3 条前半），但复盘只展示"恐怖蛙附体了"，没教"下次恐慌时该怎么办"——后半句"被驯服"差一步。
**补法：每种情绪兽的 note 增加一条可执行应对建议。**

### 6. 检查单的知识/思维配比
部分条目偏知识记忆（"换证书必查三件套"）。属拓展知识层可接受，但值得加标签控制比例。
