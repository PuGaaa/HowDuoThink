# 登录体系 v2：手机验证码登录 + 多身份绑定（账号互通）

## 架构决策
- **不拆独立认证中心**：App/Web 共用同一后端 + users 表，JWT 即无状态认证权威，互通已是事实
- **多身份绑定**：users 表加 `phone` 列（unique nullable）——同一账号可挂 密码/GitHub/手机号 三种身份；Web GitHub 注册后绑定手机号 → App 验证码登录进的是同一账号（互通的关键）
- **短信通道可插拔**：`core/sms.py` 抽象 Sender；DevSender（验证码写日志+仅 dev 响应回显）v0 联调；AliyunSmsSender 占位（ALIYUN_SMS_* 环境变量齐备后启用）；将来一键登录接阿里云号码认证服务 SDK，用户模型已预留 phone 位
- **一键登录 v0 完全不做**（按你的选择）

## 后端改动
1. **表结构**：users 加 `phone TEXT UNIQUE`（db.init 轻迁移，照 password_hash 先例）；新表 `sms_codes(phone PK, code, expires_at, used)`
2. **core/sms.py**：`send_code(phone) -> {devEcho?}`——生成 6 位码、存 sms_codes（60s 重发限频、10 分钟有效）、按 SMS_PROVIDER 分发；DevSender 日志输出 + dev 模式回显
3. **features/auth**：
   - models：SmsSendBody / PhoneLoginBody / BindPhoneBody（CN 手机号正则 1[3-9]\d{9}）
   - service：send_sms_code（限频校验）、phone_login（验码 → 按 phone 找用户/创建 ph- 用户 → token）、bind_phone（已登录用户绑定，已绑他人手机则 409）
   - router：POST /api/auth/sms/send（公开）、POST /api/auth/login/phone（公开）、POST /api/me/bind-phone（登录态）
4. **测试 6 用例**：dev 发送回显、手机登录建号、二次登录同 uid、错码 401、过期码 401、绑定后手机登录返回原 uid + 60s 限频 429

## App 登录页改造
- 顶部 tab 切换：「验证码登录」/「密码登录」（默认验证码，符合国内习惯）
- 验证码 tab：手机号输入 + 验证码输入行内「获取验证码」按钮（60s 倒计时）→ 登录
- 密码 tab：现有表单原样
- 底部提示改为「Web 端注册的账号可直接登录 · 登录后互通」；去 GitHub/一键登录按钮

## 明确不做
独立认证中心服务、一键登录 SDK 接入、任务计数跨端同步（云同步 feature 另行批次）

## 验收
pytest 全绿（新 6 用例）；浏览器走验：发送验证码（dev 回显）→ 手机登录建号 → profile 显示新用户 → Web GitHub 账号绑定手机 → 手机登录返回同一账号；git 提交
