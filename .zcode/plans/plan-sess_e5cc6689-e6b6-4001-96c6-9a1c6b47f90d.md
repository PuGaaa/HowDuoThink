# Debugo 长期出题总纲设计

## 执行内容（唯一动作）
将完整出题总纲写入 `docs/出题总纲.md` 并提交。总纲基于：理念四层十一思 + 现状盘点（17 关/六章）+ ROADMAP 既定方向（P5c 安全/容量、100 关=8×12）+ 审计缺口。要点如下：

### 终局蓝图
8 章 × 6~12 关 ≈ 66 官方关 + 社区投稿 → 100 关。新增两章（对齐 ROADMAP P5c）：
- 第 7 章 安全攻防（pact：每一个便利的捷径，都可能是别人进来的门）
- 第 8 章 架构演进（pact：故障的种子在设计时种下——容量、限流、降级是偿还）

### 思维覆盖矩阵
现状实测：推理层三思（每关机制性训练）最强、架构设计 8 关、程序设计 3、产品思维 2、**安全思维 0 专属**。目标：50 关时每思 ≥5 关专属载体；此后每批出题前过矩阵查缺。

### 批次计划（前 6 批详细到每关规格，B1~B6 共 30 关）
- **B1 短板补强**（runtime 3 + build 1 + observability 2）：事件循环阻塞 / TIME_WAIT 耗尽 / 闭包泄漏续集 / CI 缓存污染 / 告警风暴 / 直方图桶误判
- **B2 安全思维线**（新章首发 6 关）：密钥进 git 历史 / IDOR 越权 / 日志泄露敏感信息 / 竞态提现（联动并发章）/ SSRF / 供应链投毒
- **B3 评审线铺开**（评审现场皮肤 ×4，每章 1 结业评审）：限流与证书轮换 / 依赖治理 / 容器限额扩缩容 / 指标体系告警规则
- **B4 产品思维线**（决策现场新皮肤试点 ×4）：回滚还是硬扛 / 灰度决策 / 大促前安全隐患上还是延 / 错误预算烧完冻结还是继续
- **B5 高噪声复合**（master 篇进阶 4 关）：击穿遇慢查询双因叠加 / 假线索误导 / 依赖超时级联雪崩链 / 修数据脚本修出新事故
- **B6 架构演进章**（新章首发 4 关）：限流穿透 / 降级演练翻车 / 重试风暴 / 弹性伸缩慢半拍

每关规格含：章/难度/标题草案/真实故障原型/主训思维/次训思维/皮肤/情绪兽出场设计。

### 持续产出机制
出题八件套模板（主训思维/次训/真实原型/皮肤/情绪兽/检查单配比≥3:1/危险动作/层契约）；社区投稿按章开放模板引导；AI 起草管线（ROADMAP 1.2）辅助；双检门禁 + 思维配比检查。

### 配套数据清理（随总纲第一步执行）
- c-sms 归章修正：data → build（第三方依赖归属）
- part 字段错位清理（ssl-chain/dns-hijack 的 case 级 part）

### 节奏
每批 = 一个迭代（约 1~2 周）；每批出题前过覆盖矩阵查缺、出题后更新矩阵；分四笔提交（总纲文档 / B1 / B2 / 配套清理），B3~B6 规格随总纲一次定稿、逐批执行。
