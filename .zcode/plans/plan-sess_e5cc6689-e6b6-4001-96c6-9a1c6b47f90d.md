# 「通用」四项功能落地批次

## A. 关于页（纯前端，最快）
1. 新页 `pages/about/about`：吉祥物头像 + 名称 + slogan「看症状 · 立假设 · 算成本 · 定根因」+ 版本号 + Web 社区站链接（localhost:3000）+ 技术栈致谢（uni-app X / FastAPI / Nuxt / Vue）
2. pages.json 注册；profile「关于」行点击跳转（其余三行点击行为随 B/C/D 各自落地）

## B. 每日一题
1. `app/utils/daily.ts`：`todayKey()`（YYYY-MM-DD）+ `dailyCase()`（日期字符串 hash → ALL_CASES 确定性选题，同一天人人同题）+ `isDailyCase(id)` + `dailyDone()`（storage 记录完成日期）
2. 首页 continue 卡上方加「今日一题」横幅：今日案例标题 + 去挑战；完成后变薄荷完成态
3. 任务系统接入：`tasks.ts` 加每日任务 d-daily「完成今日一题」（metric `dailycase`）；play 通关时 isDailyCase → bumpTask('dailycase', 1)
4. profile「每日一题」行：显示今日题名，点击跳转挑战（完成后显示 ✓ 已完成）

## C. 学习提醒
1. `app/utils/reminder.ts`：偏好存 storage（think_reminder: {on, hh, mm}，默认 21:30）；H5 Notification API（申请权限 + 60s 轮询到点通知「今天的学习时间到了」，当日去重）
2. profile「学习提醒」行：uni.showActionSheet 选 20:00/21:00/21:30/22:00/关闭，值实时回显
3. 行内注明「页面打开时生效」（原生推送等打包 App 后接）

## D. 检查单云同步（后端新 feature，Bearer 通道已备）
1. `server/features/progress/`：models（ProgressSync：cases map + 检查单聚合）+ service（GET 返回用户 blob / POST 覆盖存储，按 user_id 一行 JSON）+ router 挂载 main；users 已有表，新表 progress(user_id PK, blob, updated_at)
2. App `utils/sync-progress.ts`：
   - 登录后 onShow 拉取合并（策略：本地已解关卡保留，服务器有而本地无的补入；冲突取 solved=true 并集）
   - saveSession 后防抖 2s 全量上传（仅登录态，Bearer）
3. profile「检查单云同步」行三态：未登录灰字「登录后可用」；已登录显示上次同步时间 + 点击手动同步
4. 测试 3 用例：未登录 401、上传后拉取一致、覆盖语义

## 验收
- pytest 全绿（18+3）
- 浏览器走验：关于页渲染、每日一题完成流（玩今日题 → 横幅变完成 → 任务页 d-daily 勾选）、提醒设置与通知、双端同步（登录 → 本地进度上传 → 清库重登拉取合并）
- 分四笔提交（A/B/C/D）
