# 篇章锁：轻量序贯 + 跳级挑战（不做自由模式开关）

## 锁定规则（判定全部由已有 solved 进度派生，零新存储）

1. **关**：章内自由顺序，不锁
2. **章**：前一章破 ≥1 关即解锁（第 1 章恒开）
3. **篇**：前一篇所有章各破 ≥1 关即解锁（第一篇恒开）
4. **跳级挑战**：锁定的章，其 order 最小的第 1 关始终可玩；通关它 → 本章解锁（篇锁条件随之推进）。解锁状态无独立存储，通关挑战落 solved 后锁自动打开

## 改动清单

1. **`app/data/chapters.ts`** 新增纯函数：
   - `chapterSolvedCount(chapterId)` / `isChapterUnlocked(chapterId)` / `isPartUnlocked(partId)`（按 CHAPTERS 顺序找前章/前篇）
   - `chapterChallengeCaseId(chapterId)`：该章 order 最小关（本地+casepack 合并后取第一，社区关规则一致）
   - `isCasePlayable(caseId)`：所在章已解锁 ∥ 是该章挑战关
2. **`app/components/chapter-cube/chapter-cube.uvue`**：加 `locked` prop——锁定态置灰（降饱和底色 + lock-ink3 图标，图标库已有该资源）+ 底部文案换成"通关上一章 1 关或挑战本关解锁"
3. **`app/pages/index/index.uvue`**：传 `:locked`；`openChapter` 判锁——锁定的章弹 uni.showModal「直接挑战本章第 1 关？」确认后进 play；「继续闯关」改为取第一个 isCasePlayable 且未 solved 的关（挑战关未破时天然命中它）
4. **`app/pages/chapter/chapter.uvue`**：`openCase` 加 isCasePlayable 拦截（纵深防御），锁定关条目置灰 + lock 图标
5. **`app/pages/play/play.uvue`**：onLoad 加 `isCasePlayable` 守卫，不通过 toast「先通关上一章，或从章节页发起挑战」+ navigateBack（复用现有"案例不存在"兜底模式）
6. **不做**：自由模式开关（长期会贬值成作弊按钮，跳级挑战已覆盖老手/演示场景）；web 端不涉及（无游玩交互）
