# Web 社区端 + 后端 + App 同步 — 规划

## 一、核心数据模型：三对象（防丢字段的核心设计）

```
Submission（用户投稿：轻量，3 必填）           GitHub 登录后提交
    ↓ 转化（作者/AI 辅助：拆动作、设计干扰项、标 tests/效应）
Case（App 关卡：现有完整 schema + 来源字段）    发布门禁校验后进 casepack
    ↓ 投影（派生）
Article（Web 解决逻辑：步骤化静态展示）          Web 列表/详情只读
```

### Submission 字段（防"填太多"：必填 3 项，其余选填折叠）

| 字段 | 必填 | 上限 | Case 落点（映射保证不丢） |
|---|---|---|---|
| title（一句话症状）| ✓ | 40 字 | case.title / 现场症状标题 |
| symptom（现象描述，MD）| ✓ | 1200 字 | scene.symptoms（text 证据）|
| resolution（最终解决过程，按步骤叙述）| ✓ | 2400 字 | expertChain 骨架 + actions 序列 + article.steps |
| key_error（关键报错原文）| ○ | 600 字 | scene.symptoms（error 证据）|
| timeline（何时开始/关联变更）| ○ | 300 字 | scene.timeline |
| lessons（经验 1~3 条）| ○ | 3×80 字 | lessons |
| stack_tags / domain_hint | ○ | 选择器 | domain/layer 参考 |
| （转化时补齐）| — | — | tests 绑定 / 效应标注 / 干扰假设 / rootCauses / difficulty |

### 表结构（SQLite，复杂结构用 JSON 列 + 索引列，schema 仍迭代期最务实）

- `users`：github_id / login / name / avatar / role（user/editor/admin）/ created_at
- `submissions`：上述字段 + user_id / status（pending·accepted·rejected·archived）/ review_note / 时间戳
- `cases`：id(slug) / submission_id（可空=官方题）/ author_id / status（draft·published）/ version（递增，同步用）/ **payload JSON**（完整 case schema，发布前过门禁）
- `articles`：source_type（case·submission）/ source_id / title / layer / steps JSON（步骤化解决逻辑）/ lessons JSON / author / published_at

## 二、后端（server/，Python 3.12 + FastAPI + SQLite）

```
server/
  main.py            # FastAPI 入口 + 路由
  models.py          # Pydantic：Submission/CasePayload/Article/CasePack（字段完整性由 Pydantic 强校验）
  db.py              # SQLite（sqlite3 + WAL）
  oauth_github.py    # GitHub OAuth（authorize/callback/换 token/拉用户/签发自有 JWT cookie）
  gate.py            # 发布门禁：写作规范红线的 Python 版（六部件完整、tests 绑定完备、
                     #   每干扰假设有排除路径、证据非空自洽标记、expertCost 合理）——
                     #   语义类红线人工勾选，结构类红线代码强制
  data.db
```

API：
- `GET /api/oauth/github/callback` — 登录
- `POST /api/submissions` / `GET /api/me/submissions` — 投稿与状态
- `GET /api/solutions?layer=&page=` / `GET /api/solutions/:id` — Web 列表/详情
- `POST /api/cases`（editor：submission→case 转化提交，过 gate 才入库）
- `GET /api/casepack?since=<version>` — **App 同步**：仅 published，按 version 增量，payload 全字段

发布双保险：Pydantic 结构校验（代码强制）→ 语义红线人工勾选 → 可选子进程跑 `validate.mjs` 二次机检（Node 工具链仍在）。

## 三、Web 端（web/，Nuxt 3 + Vue，与 App 同生态）

页面：`/`（投稿 CTA + 最新解决逻辑）/ `/submit`（渐进式表单：必填 3 项展开，选填折叠）/ `/solutions`（层筛选列表）/ `/solutions/[id]`（步骤化解决逻辑详情）/ `/me`（我的投稿状态）。登录态走 JWT cookie + middleware。

## 四、App 端同步（本期做到"拉取+落库+提示"）

启动时 `GET /api/casepack?since=<本地版本>` → 本地校验（字段完整性）→ 存 storage → 章节地图合并远端关卡（"可玩"标记）。深度的章节远端化放 M3。

## 五、里程碑

- **W1**：FastAPI 骨架 + GitHub OAuth + submissions API + SQLite + Pydantic 模型
- **W2**：Nuxt 站（投稿表单 / 列表 / 详情 / 我的）+ solutions 投影
- **W3**：Case 转化提交 API + gate 门禁 + casepack API
- **W4**：App 端 casepack 拉取与本地合并
- 与 M2 并行：社区投稿进来 → 按 schema 转化成关卡（内容飞轮启动）

## 六、v1 明确不做

富文本附件/截图上传、评论/点赞、投稿直接发布（必须转化+门禁）、管理后台 UI（先用 API+脚本）、多语言、邮件通知。
