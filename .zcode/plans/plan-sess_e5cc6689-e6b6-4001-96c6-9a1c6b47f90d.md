B19：AI 基建（LangChain 模型 I/O + 自研编排）+ AI 起草管线 + 案例库 RAG 对话

## 技术栈定稿（两轮决策）
- **模型 I/O 层**：LangChain——`langchain-core` + `langchain-openai`（requirements.txt 新增）；ChatOpenAI(model=glm-4.5-flash, base_url=智谱兼容端点) + OpenAIEmbeddings(model=embedding-3, dimensions=1024)，key 走 `ZHIPU_API_KEY` 环境变量
- **编排层**：自研直线流程（先自研、LangGraph 演进）——service 函数全部写成**纯节点**（retrieve/generate/critique 各自独立、无隐藏状态），将来上 LangGraph 时包成节点零返工；此演进路径写进 ai/client.py 注释
- **检索层**：SQLite `ai_index` 表存 embedding（JSON 数组）+ Python 暴力余弦——132 案例 ≈ 400 向量，不引入向量库
- **降级链**：未配 `ZHIPU_API_KEY` → chat/search 返回结构化提示 + 关键词 LIKE 降级检索；ai-draft 退回现有机械骨架

## Part A：AI 域（server/features/ai/，router/service/models/client 四件）
1. `core/config.py` 新增：`ZHIPU_API_KEY`、`AI_BASE_URL`（智谱 openai 兼容端点）、`GLM_MODEL`、`GLM_EMBED_MODEL`
2. `core/db.py` 新增 `ai_index` 表：id, source_type, source_id, chunk_kind(overview|resolution), content, embedding(JSON), model, updated_at
3. client.py：`chat_model()/embeddings_model()/available()`（LangChain 实例惰性构建）
4. service.py（纯节点设计）：
   - `node_retrieve(query, k)`：embed → 余弦 top-K；无 key → LIKE 关键词降级
   - `node_answer(question, chunks)`：system prompt（好多星排错助手：可能原因引案例/检查单步骤/引用来源，不编造）→ ChatOpenAI.invoke
   - `chat(question, uid)`：retrieve → answer 组装 + sources[{caseId,title}]；内存限速 10 次/分/用户
   - `index_case/reindex_all`：published payload → 每案例 2 块（overview=标题+症状+层契约；resolution=根因+专家链结论+检查单）→ embed → upsert
5. router：`POST /api/ai/chat`（登录）、`GET /api/ai/search?q=`、`POST /api/admin/ai/reindex`；main.py 挂载
6. `features/cases/service.py` publish_case 成功后增量 `index_case`（失败不阻塞发布，记日志）

## Part B：AI 起草管线
`POST /api/admin/submissions/{sid}/ai-draft`（features/ai/service 里实现，submissions/router 挂路由）：
投稿素材 → ChatPromptTemplate 按《案例写作规范》预填六部件（假设平权/每干扰项有排除路径/L≥2 危险动作/why 必写/lessons 带 principle/六维定级）→ JSON 容错解析 → 合并机械骨架（素材字段保留：症状/关键报错/时间线/教训原文）→ 落库 draft。无 key 退回现有机械骨架；响应带 `aiGenerated: true/false` + `warnings[]`。
